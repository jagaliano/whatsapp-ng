## Scope

- Extend `RunReportService`, not a second reporting owner. Keep existing final stats unchanged and independently selectable. Add default-off validated global `replyReporting` flags: `changedFiles`, `interimText`, `liveActivity`. Capture eligibility/revisions at native input consumption; later opt-in never exports existing work. Reuse atomic configuration writes and existing terminal/verified-owner reply controls. Enabling warns about sharing workspace-relative paths and intermediate assistant text with allowed chats.
- Changed-file summary: only observed successful `write`/`edit` calls with a valid workspace-relative path. Do not run a Git diff or read file contents. Exclude outside-workspace, hidden/auth/credential paths and unsafe/oversized labels. Report at most twenty unique paths, mark incomplete coverage, and describe them as observed successful tool calls—not proof that no other files changed. Combine with enabled final stats into one bounded text after an accepted automatic final; legacy/explicit-text suppression and unknown/cancelled/failed finals do not create a report.
- Interim text: only completed assistant text in a non-final tool-bearing response at the turn boundary, never token deltas, thinking or tool results. At most four messages per consumed input, each at most 4 KiB; omit oversized content rather than silently truncating it. Serialize/coalesce pending work, withdraw unsent interim updates on finalization/reset, and never let reporting suppress the final answer or delay core lifecycle completion.
- Live activity: at most one created message per owned input and one coalesced pending edit, no faster than every two seconds. Show only bounded tool names/status. Edit only the exact retained own-message key in the same verified chat/account. A failed/unknown send or edit stops activity for that input; no retry or replacement-message spam. Timers and pending work are cancelled on stop/Off, disconnect, revocation or session replacement. Already-issued network effects cannot be recalled; cancellation may leave the last observed status visible.
- Combined reporting work retains the existing eight-slot bound and sender-settlement ownership, including unknown deliveries across resets. Preserve immutable conversation scopes, pause/admission guards and progress-purpose duplicate-suppression semantics. No terminal forwarding through C1; C3 remains separately consented.
- Add one pure conservative outgoing WhatsApp formatter for assistant-authored text: common balanced Markdown bold/strike, headings and HTTP(S) links become readable WhatsApp text. Preserve code bodies, inline code, URLs, whitespace and malformed/unsupported constructs instead of guessing or deleting content. No fetching, summarization, new model call or HTML rendering. Apply only at owned assistant-text delivery/tool-caption boundaries, after provenance checks; keep manual UI/control text, input hashes, quotes, speech payloads and media bytes unchanged.
